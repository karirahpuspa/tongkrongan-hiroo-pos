## 1. Ringkasan

Tongkrongan Hiroo adalah kafe F&B (menu Rp5.000-Rp25.000 per item) yang masih mencatat pesanan, transaksi, dan keuangan secara manual dengan buku. Saat jam ramai (terutama malam minggu dengan live music), banyak transaksi tidak tercatat sehingga pemasukan tercatat berbeda dari uang yang diterima (selisih hingga sekitar Rp600.000 per malam, keterangan lisan owner, belum diverifikasi data).

Produk ini adalah aplikasi web kasir: kasir memulai shift, memilih menu dan jumlah, mengisi nama pelanggan dan catatan, mencatat pembayaran (tunai/QRIS), mencetak struk, dan menyampaikan pesanan ke dapur/penyaji secara manual. Transaksi tersimpan di database dan direkap ke Google Sheets. Di akhir shift, kasir menutup shift dan sistem menghitung selisih kas. Owner melihat laporan untuk mencocokkan pemasukan dengan uang yang diterima.

Hasil akhir adalah **prototipe MVP** untuk demonstrasi dan validasi, belum untuk operasional produksi.

## 2. Tujuan dan Indikator Keberhasilan

| Tujuan | Indikator |
|---|---|
| Pencatatan pesanan lebih cepat dan mudah untuk staf awam | Kasir menginput satu pesanan lengkap hanya dengan panduan singkat |
| Transaksi terlewat dan selisih pemasukan berkurang | Simulasi 20 pesanan berturut-turut: seluruhnya muncul di laporan dan spreadsheet |
| Selisih uang dapat dilacak | Setiap shift menampilkan kas seharusnya, uang fisik, dan selisih |
| Owner mudah memeriksa pemasukan | Total laporan sama dengan total input |
| Akses keuangan terbatas | Kasir tidak dapat membuka laporan keuangan |
| Tanpa rekap manual | Data tersimpan otomatis ke database dan spreadsheet |

Manfaat bisnis (berkurangnya selisih pemasukan) **tidak boleh diklaim tercapai** sebelum sistem dipakai dan dievaluasi secara nyata.

## 5. Alur Utama

```
Kasir login (tablet bersama)
  -> "Mulai shift": kasir mengisi jam mulai dan modal awal kas secara manual -> shift aktif
  -> pilih menu + jumlah + nama pelanggan + catatan pesanan (opsional)
  -> backend hitung total dari harga menu
  -> buat pesanan (pending_payment)   [kasir boleh ubah isi pesanan di sini]
  -> pilih metode:
       Tunai  : isi uang diterima -> sistem hitung kembalian
       QRIS   : isi nomor rekening/e-wallet + nama pemilik
  -> pembayaran paid -> pesanan processing
  -> struk tampil/cetak; kasir menyampaikan pesanan ke dapur/penyaji secara manual (lisan atau struk)
  -> pesanan diserahkan ke pelanggan -> kasir/owner menandai completed
  -> transaksi tersimpan di MySQL lalu dikirim ke Google Sheets
Akhir shift: kasir "Tutup shift"
  -> sistem catat jam selesai, hitung kas seharusnya
  -> kasir isi uang fisik -> sistem hitung selisih -> tercatat otomatis
Owner login (laptop)
  -> laporan: total, tunai/QRIS, menu terlaris, per kasir, selisih per shift
  -> filter tanggal, ekspor/cetak
```

**Pembatalan:** hanya saat `pending_payment`, wajib alasan.

**Tanggal bisnis:** semua transaksi dan laporan dikelompokkan berdasarkan **tanggal mulai shift**, sehingga transaksi setelah pukul 00:00 pada shift malam minggu tetap masuk laporan hari yang sama.

## 7. Aturan Bisnis
1. Pembayaran dilakukan **sebelum** pesanan diproses.
2. Isi pesanan hanya dapat diubah sebelum dibayar; setelah dibayar, koreksi oleh owner.
3. Pembatalan hanya sebelum status processing.
4. Harga item disimpan sebagai **snapshot** saat pesanan dibuat; perubahan harga menu tidak mengubah riwayat.
5. Hanya owner yang menentukan dan mengubah harga.
6. Sumber data utama adalah MySQL; Google Sheets hanya media rekap.
7. Kas seharusnya shift = modal awal + total tunai pesanan paid pada shift tersebut. QRIS tidak masuk kas laci.
8. Refund (F2) dilakukan manual di luar aplikasi, hanya dicatat.

## 11. Kebutuhan Non-Fungsional
- **Keamanan:** bcrypt, validasi input di backend, role check di backend, `.env` tidak di-commit, CORS dibatasi, validasi file upload, data rekening QRIS dibatasi aksesnya.
- **Kinerja:** simpan pesanan terasa instan (< 2 detik pada jaringan normal) [Asumsi].
- **Keandalan:** transaksi tidak hilang saat Sheets gagal; tidak ada transaksi ganda.
- **Perangkat:** **responsif penuh** untuk laptop, tablet/iPad, dan HP (pendekatan satu kode untuk semua ukuran layar, memakai breakpoint). Perangkat utama: tablet (kasir) dan laptop (owner); HP tetap harus dapat dipakai. Browser modern.
- **Konektivitas:** online only; tanpa mode offline.
- **Data:** data uji berupa data dummy dari menu Hiroo. Aplikasi hanya menyimpan nama panggilan pelanggan dan data rekening QRIS sesuai kebutuhan di atas.

## 15. Risiko

| Kasir lupa menutup shift | Peringatan saat login dan tutup paksa oleh owner (P1) |
